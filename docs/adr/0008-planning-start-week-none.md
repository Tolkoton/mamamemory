# ADR-0008: `planning.start` бере `week: bool | None = None` (поправка до Seam add-or-plan)

Статус: прийнято 2026-11-07 (архітектор, двобічні двері; власникові — як інформація). Відступ від
`.engine/slices/add-or-plan.md` § Seam і § Decisions (with WHY) Q2.

## Контекст
Запечатаний контракт add-or-plan фіксує `planning.start(..., week: bool = True)` з причиною «без неї — як F2
(запечатані тести F2 лишаються чинними)». Той самий Seam дає `week=True` нову поведінку: без надиктованої задачі —
не «Не зрозуміла задачу…», а план із задач Tasks чи «Задач на тиждень немає…». Запечатаний тест F2
`tests/test_several_tasks_planning.py::test_message_without_any_task_changes_nothing` кличе `start()` без `week` і
чекає «Не зрозуміла задачу…»; з `True` за замовчуванням він падає (відтворено наглядачем: 1 failed, 528 passed). Два
речення контракту суперечать одне одному.

## Варіанти
- `week: bool = True` — буква контракту; ламає запечатаний тест F2, потрібне перепечатування several-tasks (дія
  власника) — саме те, чого Q2 хотіла уникнути.
- `week: bool | None = None` — `None` рівно як F2; `True` і `False` — як у контракті.
- `week` обов'язковий — змінює всі виклики й тести F2.

## Рішення
`week` за замовчуванням `None`. `None` — поведінка F2 (Tasks читаються, питання про важливість, без задачі — «Не
зрозуміла задачу…»). `True` — «сплануй тиждень», як у контракті. `False` — «додай задачу». Маршрутизація
(`assistant.handle_message`) завжди передає `bool`: `new_task` → `False`, `plan_week` → `True`; `None` досяжний лише
прямим викликачам — запечатаним тестам F2.

## Наслідки
- Запечатані тести F2 лишаються чинними без перепечатування (мета Q2).
- `start()` має три стани замість двох; той, що продукція не вживає, — лише для сумісності.
- Новий викликач, що забуде `week`, дістане поведінку F2, не режим «додати», який просив власник.
- Відкат — малий: коли тести F2 перепечатають, `week` стає обов'язковим `bool`.

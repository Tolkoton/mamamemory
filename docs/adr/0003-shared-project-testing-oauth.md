# ADR-0003: Поки — спільний проєкт pocket-lawyer-431614 і тестовий режим входу Google

## Status

ACCEPTED

Date: 2026-10-24

## Context and Problem Statement

Архітектор радив окремий проєкт Google Cloud для mamamemory: екран входу Google, його режим, ліміт користувачів, безкоштовна база Firestore і доступи належать проєкту, а не застосунку (support.google.com/cloud/answer/15549945). Для входу маминого Gmail з дозволами на Calendar і Tasks були варіанти: (а) тестовий режим — вхід заново щотижня; (б) робочий режим без перевірки — один раз екран «неперевірений застосунок»; (в) перевірка Google.

## Decision Outcome

Рішення власника, дослівно:
- проєкт: «Проект. Поки що не робимо. Поки воно ще зарано, тим бавитись.»
- вхід: «Так, лишаємо тестовий режим, нічого не перемикаємо.»

(2026-10-24, розмова з master-architect; ≈ 08:45–08:57 UTC, відновлено за часом створення ADR-0004 і ADR-0005, записаних тієї ж хвилини.) «Проект…» — відповідь на питання 1 огляду M2 («Окремий проєкт Google Cloud для mamamemory… Порада: так, окремий.»); «лишаємо тестовий режим» — відповідь на уточнення А («лишаємо тестовий режим, як він зараз налаштований у проєкті… мама раз на тиждень входить заново. Правильно?»).

Наслідки:
- mamamemory працює в `pocket-lawyer-431614` (docs/infra.md); екран входу спільний з Pocket_lawyer, тож мама бачить його назву;
- вхід у тестовому режимі: мамин акаунт — тестовий користувач; токен живе 7 днів, мама входить заново раз на тиждень;
- база mamamemory — окрема названа база Firestore у цьому проєкті (ADR-0004), не змішується з даними Pocket_lawyer;
- двері двобічні: поки даних мало, перенесення в окремий проєкт — експорт кількох МБ.

## Звірка з цілями
- служить: C2, C3
- вибір між варіантами розв'язав: рішення власника вище; P1 (найпростіше зараз)
- не-цілі й обмеження: N3 — без магазинів; C1 — сервіси й регіони не змінюються

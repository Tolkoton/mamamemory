# M1 — раунди master-critic (domain)

- Раунд 1 — MASTER_CRITIC_REVISE: 3 BLOCKING (мамині Calendar/Tasks поза списком premises для C1 → P-CAL; дублі задачі між Tasks і Calendar → закривати в Tasks; вихід кроку 3 — «не вмістилось» і мамині межі часу), 4 NOTE (джерело «Дані під акаунтом» → ADR-0001; Журнал роботи → у Справи; «п'ять кроків» → чотири, P1 прибрано з M1; факт про 7-денний refresh token → P-AUTH). Усе виправлено.
- Раунд 2 — MASTER_CRITIC_REVISE: 1 BLOCKING (збережена розстановка плану застаріває, поки мама перемикається → зберігати лише входи, розстановку рахувати наново при показі й перед записом), 7 NOTE (неповне ранжування, Розкладач при двох схожих справах, «текст із документа» як можливість, а не крок, «підтримка ≠ тонше»). Виправлено.
- Раунд 3 — MASTER_CRITIC_PASS. 5 NOTE застосовано: P-CAL — тверда умова перед slice запису в Calendar/Tasks; запис роботи без справи — законний стан; Асистент — тонкий маршрутизатор; мамині межі часу пропонуються з минулого планування; Розкладач — перший кандидат на PoC у M2.
- Guardian після PASS — нуль BLOCK, 7 NOTE: крок 2 розбито на короткі питання по одному (межі часу лишено: без них план ставить задачі на ніч — критик, раунд 1); Розкладач повідомляє текстом, уголос лише на прохання (C4); Журнал роботи — простий список, прив'язка до справи необов'язкова; P1 у матриці перенесено на M2; N5 — типові налаштування календаря, власних нагадувань немає; P-CAL і P-AUTH — першими в M2, вибір щодо входу — одним питанням власникові.

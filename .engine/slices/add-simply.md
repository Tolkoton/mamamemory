# Slice add-simply — поправка F2 за словом власника 2026-11-14 (скриншоти телефону) — planning artifact

## Goal
Власник, 2026-11-14: «Коли його просять додати таску, значить треба що? Додати таску, а не мудрувати. Питати коли,
спитати в котрій годині, а не коли ти робиш таски. Це дурне питання»; «Оце, що ти вмієш, має бути, відкрилося,
схлопнулося. А не кожен раз нове друкується». Скриншот: на «додати таску» — «Скільки часу займе «Додати таску»?», далі
«Коли ви взагалі можете робити задачі?…»; гайд надруковано двічі. Треба: (1) «додай задачу …» не питає ні тривалості, ні
меж — лише «коли», якщо час не названо; (2) «додай таску» без самої задачі — «Яку задачу додати?»; (3) кнопка «Що я
вмію» розгортає й згортає один гайд. Вимірний сигнал: тести; smoke на справжній моделі; прохід власника.

## Premise verified
- Режим `add` (add-or-plan): `planning.start(..., week=False)` → чернетка `mode: "add"` → `next_question`: тривалість →
  межі → показ плану; «так» — запис (код F2).
- Розбір задач (`_parse_tasks`, Flash-Lite) дає `title`, `needs_time`, `start_local`, `day`, `duration_min` (F1–F2;
  smoke_several_tasks). На «додати таску» — назва «Додати таску» (скриншот власника 2026-11-14).
- Розміщення: задача з `start_local` ставиться саме на цей час (F1 one-task-to-calendar, several-tasks).
- P-WHEN (Flash-Lite розбирає коротку відповідь на «коли?» — «о десятій», «у понеділок о третій», «завтра о пів на
  десяту», «у середу» — у дату й час чи лише день) — `unverified`; smoke цього slice.

## Out of scope (deliberately)
- «сплануй тиждень» (`mode: "week"`) — питання важливості, тривалості, меж лишаються (власник казав про «додай»);
- показ плану й підтвердження «так» перед записом — без змін;
- задачі без часу (`needs_time: false`, «купити хліб») — як було (Google Tasks після «так»);
- фіксовані тексти на «ти» — картка 750;
- «додай задачу» при відкритій чернетці тижня «питаю» — задача дописується до плану тижня з його питаннями (як було).

## Seam (contract)
- `planning.ADD_DEFAULT_MIN = 60` — тривалість задачі режиму `add`, коли мама її не назвала. PROVISIONAL — owner
  ratification pending (AUTONOMOUS, escalations.md; cost-to-reverse — одна константа).
- `planning.next_question(draft, ...)` для `mode == "add"`: ніколи `priorities`, `duration` чи `limits`; задача на час
  (`needs_time`, не записана, не прибрана) без `start_local` і без `when_set` — `Question("when", plan_id, None)`
  (перша така в порядку `order`); інакше `None` (показ плану). Тривалість `None` такої задачі при розміщенні —
  `ADD_DEFAULT_MIN`. `mode == "week"` і чернетка без `mode` — як було.
- Текст питання `when`: день відомий (`constraints.day`) — «О котрій годині «<назва>»?»; ні — «Коли «<назва>»? Скажіть
  день і годину.».
- `planning.try_answer_when(session, plan_id, text, *, ai, calendar, store, now, config) -> Reply | None` (у
  `assistant.SHORT_ANSWERS["when"]`; `QuestionKind` дістає `"when"`): модель `parse_when` (Flash-Lite) за схемою
  `WHEN_SCHEMA {is_answer: bool, day: "YYYY-MM-DD" | null, start_local: "YYYY-MM-DDTHH:MM" | null}`
  (обов'язкові всі), підказка з «зараз», зоною календаря, назвою задачі й відомим днем. `is_answer: false` → `None`
  (чернетка без змін — як stuck-question). `start_local` → задача дістає `start_local` і `constraints.day` цієї дати. Лише `day` → `constraints.day`, і
  те саме питання вже з «О котрій годині». `is_answer: true` без дня й часу («будь-коли», «не знаю») — те саме питання
  ще раз, чернетка без змін (розміщення навмання немає: власник — «спитати в котрій годині»). Застаріла чи чужа чернетка — як `try_answer_duration`
  (`_too_old_to_answer` → `None`; не та / не «питаю» → «NOT_ACTUAL»). Далі — `_advance` (наступне питання чи план).
- Правки голосом (voice-edits): `_edit_task` виду `not_before` і виду `move` лише з `day` (без `start_local`) ставить
  задачі `when_set: true` (у будь-якому режимі; `week` поле не читає) — питання «коли» на неї немає, розміщення — як
  було (межі мами чи без них), план показується знову. `move` з `start_local`, `remove`, `untimed` — як було.
- `try_answer_when` з `start_local` у минулому — далі як для названого часу поза горизонтом (`NAMED_OUTSIDE`, як було).
  `assistant` не додає `"when"` до `refused_kind` для `dismiss_asking` (той стосується лише плану тижня).
- `planning.start(..., week=False)`: якщо всі розібрані задачі — сама просьба додати (у назві лише слова «додай /
  додати / додайте / додавай», «таску / таск / задачу / завдання / справу», «нову / ще / одну / будь ласка»), —
  `Reply("Яку задачу додати?")` без чернетки; інша частина — як було.
- Сторінка: кнопка `#help` перемикає один блок `#guide` під нею (поза `#conversation`): прихований → `loadGuide` →
  текст у `#guide`, показати; показаний → сховати. Повторне відкриття — той самий блок (не новий абзац у розмові);
  `reply_to` не змінюється. `"login"` → `/auth/login`; `null` — нічого. Чистий помічник у `web/help.js`:
  `nextGuide(shown: boolean) -> "open" | "close"` (`false` → `"open"`, `true` → `"close"`).
- Does NOT do: змін «сплануй тиждень», показу плану, задач без часу, фіксованих текстів.

## Decisions (with WHY)
- Q1: Тривалість за замовчуванням 60 хв замість питання. Чому: власник — «не мудрувати»; подія в календарі потребує
  кінця. Rejected: питати тривалість лише коли час названо — найсильніше за: точний кінець; але це саме «дурне питання».
- Q2: «Коли?» — окреме коротке питання з власною моделлю розбору, не повторний розбір задачі. Чому: відповідь коротка
  («о десятій»), задача вже відома. Rejected: повторний `parse_task` на відповідь — найсильніше за: жодної нової
  схеми; але він зробить з «о десятій» нову задачу.
- Q3: Гайд — окремий блок, що розгортається, не абзац розмови. Чому: слово власника «відкрилося, схлопнулося».

## Hardest seams (test-confidence points — distinct from the contract Seam above)
- **Seam 1: «додай задачу» без питань** — «додай задачу подзвонити сестрі в понеділок о десятій» (фейк розбору з
  `start_local`, без тривалості) → одразу план (задача о 10:00 на 60 хв), жодного питання тривалості чи меж, навіть
  коли межі ніколи не збережено і `ask_limits` увімкнено; «сплануй тиждень» з тими самими фейками — питання як було.
- **Seam 2: «коли?»** — задача без часу → питання «Коли «X»? Скажіть день і годину.»; відповідь (фейк `parse_when`)
  `start_local` → план на цей час; лише `day` → «О котрій годині «X»?» і чернетка з днем; `is_answer: true` без дня й часу → те саме питання, чернетка та сама;
  `is_answer: false` → `None`, чернетка та сама; дві задачі без часу — питання по черзі.
- **Seam 2b: правка без питання** — «додай задачу … о десятій» → план → правка `not_before` 15:00 (фейк розбору
  правки) → новий план (задача не раніше 15:00), без питання «коли»; правка `move` лише з днем (середа) → план на середу; «не раніше 19:00» без збережених меж — план після
  19:00.
- **Seam 3: просьба без задачі** — розбір «додай таску» → «Додати таску» → «Яку задачу додати?», чернетки немає;
  «додати таску купити хліб» — задача (не просьба).
- **Seam 4: гайд** — `nextGuide(false) === "open"`, `nextGuide(true) === "close"`; у `index.html` є `#guide` поза
  `#conversation`.

## Invariants (rules that hold for every input in the stated domain)
- **I1** — Чернетка режиму `add` ніколи не питає тривалості, меж чи важливості.
  - Domain: будь-яка чернетка `mode: "add"` (будь-які задачі: з часом і без, з тривалістю й без, записані, прибрані,
    змінені правкою голосом;
    межі збережено чи ні; будь-які `ask_limits`, `ask_priorities`).
  - Source: слово власника 2026-11-14; Seam (`next_question` для `add`).
  - Broken by: «Скільки часу займе…» чи «Коли ви взагалі можете…» на «додай задачу».
- **I2** — Відповідь розбору `parse_when` з `is_answer: false` ніколи не змінює чернетку; `try_answer_when` повертає
  `None`.
  - Domain: будь-яка фраза, будь-які інші поля відповіді (`day`, `start_local`).
  - Source: Seam (`try_answer_when`); stuck-question (фраза, що не відповідь, — не відповідь).
  - Broken by: «які плани?» під питанням «коли?» ставить задачу на якийсь час.
